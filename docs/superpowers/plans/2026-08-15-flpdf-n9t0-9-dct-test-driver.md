# flpdf-n9t0.9 DCT test-driver consumer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the Rust `test_driver` reproduce pinned qpdf 11.9.0 `qpdf_dl_all` behavior for valid `/DCTDecode` and `/DCT` streams while retaining raw stream output, diagnostics, decode-limit policy, and writer passthrough behavior.

**Architecture:** Make both the canonical `PlDct` stage and the legacy whole-buffer adapter use the same qpdf-shaped decode implementation. The existing `test_driver` recovery/event route stays in place because it already matches qpdf's ordered raw/data/warning output; its DCT branch now drives `PlDct` and strips only the stage identifier that qpdf does not print. Use qpdf's system-libjpeg compatibility boundary when explicitly enabled, while keeping the portable Rust backend's qpdf-observed diagnostics aligned. Add flpdf-authored JPEG PDFs to the qpdf-oracle golden harness, with both filter spellings and failure boundaries covered.

**Tech Stack:** Rust workspace, `flpdf`/`flpdf-qtest-tools`, qpdf 11.9.0 pinned source and binary oracle, shell/Python fixture generator, Cargo tests and coverage checks.

## Global Constraints

- Read qpdf 11.9.0 behavior and existing flpdf code before changing implementation.
- Preserve raw bytes and the writer's encoded-stream passthrough; changing the old DCT decode rejection is intentional because qpdf decodes it at `qpdf_dl_all`.
- Do not special-case JPEG bytes or introduce sentinels/panics; use the canonical stream pipeline and existing diagnostic mechanisms.
- Generate PDF fixtures with `tests/fixtures/test_driver/generate.sh`; regenerate `.out` files only through `scripts/qpdf-test-driver-diff.sh`.
- Use RED -> GREEN TDD and run focused tests after each implementation step.
- Keep changes isolated to this branch and do not modify the qpdf source mirror.
