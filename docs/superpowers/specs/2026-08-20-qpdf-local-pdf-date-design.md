# qpdf Local PDF Date Design

## Goal

Translate qpdf 11.9.0's default embedded-file timestamp path so omitted
`/Params /CreationDate` and `/Params /ModDate` values use local wall-clock
fields and the local UTC offset, while explicit caller-supplied dates remain
byte-for-byte unchanged.

## Oracle and responsibility

The qpdf primitive is `QUtil::QPDFTime` and its two operations:

- `QUtil::get_current_qpdf_time` reads local calendar fields and a timezone
  delta (`libqpdf/QUtil.cc:868-912`; `include/qpdf/QUtil.hh:227-253`). Unix
  uses `time`, `tzset`, `localtime_r`, and `tm_gmtoff`; Windows uses
  `GetLocalTime` and `GetTimeZoneInformation`.
- `QUtil::qpdf_time_to_pdf_time` formats the delta as `Z` for zero, `+HH'MM'`
  for a negative qpdf delta, and `-HH'MM'` for a positive delta
  (`libqpdf/QUtil.cc:914-934`).

The default string is captured by a function-local static in
`QPDFJob::AttConfig::endAddAttachment` (`libqpdf/QPDFJob_config.cc:911-936`)
and is applied to both date fields in `QPDFJob::addAttachments`
(`libqpdf/QPDFJob.cc:2046-2067`).

The existing Rust `current_pdf_date` and `format_pdf_date` are divergent:
they derive UTC fields from `SystemTime`, hardcode `Z`, and recalculate the
default per `add_attachments` call. The qpdf-shaped time primitive belongs in
a dedicated private module; attachment orchestration only consumes its cached
default byte string.

## Architecture

Add `crates/flpdf/src/qpdf_time.rs` with a private `QpdfTime` value and:

- platform-specific acquisition matching qpdf's Unix/Windows source;
- a pure formatter matching qpdf's sign convention;
- a `OnceLock<Vec<u8>>` default-date cache matching the qpdf static capture;
- unit tests for zero, positive, and negative offsets and stable caching.

The FFI wrapper is isolated in this module. The rest of `flpdf` continues to
deny unsafe code, and no raw time or platform handle escapes the primitive.
`libc` is added as a direct workspace member dependency for the Unix contract;
`windows-sys` is a target-specific dependency with only the two qpdf API
feature families needed on Windows.

## Scope and non-goals

In scope:

- default dates generated by `QPDFJob::add_attachments`;
- local timezone offsets, including nonzero offsets and the zero-offset `Z`
  form;
- one-time default capture across repeated add calls in the same process;
- Windows compilation and qpdf-compatible platform API selection.

Out of scope:

- parsing or normalizing explicit `--creationdate`/`--moddate` values;
- changing `FileParamDates`' explicit UTC convenience formatter;
- adding a timezone database or a new date abstraction beyond qpdf's
  second-granularity `QPDFTime`;
- preserving the old UTC default solely for backward compatibility.

## Verification

RED tests will first pin the qpdf formatter's nonzero offset signs against the
current UTC-only implementation. GREEN tests will cover the pure primitive
and cache, while the live probe runs qpdf and flpdf in `TZ=Asia/Tokyo` and
checks the generated attachment dates for `+09'00'` versus the old `Z` output.
The final gates include Linux/macOS/Windows CI, workspace tests, strict
rustdoc, all-features clippy, qpdf module checks, and fresh patch coverage.
