# flpdf-25kg.3.13: `EncryptionParameters` / `encryption_method_e` を qpdf と 1:1 にする Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** flpdf の暗号化パラメータ表現（`EncryptionMode` / `EncryptionState`）を qpdf
11.9.0 の `encryption_method_e` / `EncryptionParameters` と 1:1 にし、`/CF` 解析・
`interpretCF`・per-object key 導出を逐語移植する。`flpdf-25kg.3.12`
(`QPDF::decryptStream`) が前提とする `e_unknown`・`encryption_V`・可変 `cf_stream`・
og キャッシュを揃えることが目的。

**Architecture:** 変更は `crates/flpdf/src/reader.rs` に閉じる。qpdf の
`QPDF::initializeEncryption` (`libqpdf/QPDF_encryption.cc:718-905`) のうち `/CF`
ループ (`:860-884`) と `interpretCF` (`:700-716`)、`getKeyForObject` (`:955-974`)、
`compute_data_key` (`:325-357`) を移植し、flpdf 独自の
`crypt_filter_modes` / `explicit_crypt_mode` / `v4_mode_for_selector` /
`r5_or_r6_mode_for_selector` / `crypt_filter_selector` の「未知はエラー」設計を
qpdf の「未知は `e_unknown` として保持し判断を遅らせる」設計に置き換える。

**Tech Stack:** Rust, cargo test, `/usr/bin/qpdf` 11.9.0（オラクル比較用）。

### 逐語移植の要点（順序を変えてはならない箇所）

1. **`interpretCF` の分岐順** (`:703-711`): `crypt_filters` の検索が
   `/Identity` 組み込みより **先**。`/CF` に `/Identity` という名前の
   エントリがあればそちらが勝つ。（probe D で実測確認済み）
2. **`/CF` ループの寛容さ** (`:862-883`): 値が辞書でないエントリは
   **黙って skip**（`crypt_filters` に入らない → 後で `interpretCF` が
   `e_unknown` を返す）。`/CFM` が name でなければ `method` は `e_none` の
   まま。**どちらもエラーにしない**。
3. **`/CFM` 不在は `e_none`** (`:865-866`): `method` を `e_none` で初期化し、
   `isName()` が偽なら `if` に入らない。
4. **`/CF` 解析のゲートは `V == 4 || V == 5`** (`:860`)。`/R` ではない。
5. **`cf_file` の既定** (`:891-904`): `/EFF` が name のときだけ
   `interpretCF(EFF)`、そうでなければ `cf_file = cf_stream`。
6. **`getKeyForObject` のキャッシュキーは `og` のみ** (`:962`)。`use_aes` は
   入らない。同一 og で string/stream の `use_aes` が食い違うと、後から呼んだ
   側は先に呼んだ側の派生キーを受け取る。
7. **`compute_data_key` は `V >= 5` で file key をそのまま返す** (`:337-340`)。

## qpdf オラクル実測（`/usr/bin/qpdf` 11.9.0）

ベースは `qpdf --static-id --encrypt --user-password=u --owner-password=o
--bits=128 --use-aes=y -- plain.pdf aes.pdf`（V=4 / R=4 / `/CF << /StdCF <<
/AuthEvent /DocOpen /CFM /AESV2 /Length 16 >> >> /StmF /StdCF /StrF /StdCF`）。
各 probe はバイト長を変えない置換で作り、xref を壊さない（D のみ長さが変わるため
qpdf が xref を再構築するが、`/Encrypt` 辞書の解釈には影響しない）。

| # | 置換 | qpdf `--show-encryption` | qpdf 終了コード | flpdf 現状 |
| --- | --- | --- | --- | --- |
| A | `/CFM /AESV2` → `/CFM /AESVX` | stream/string/file = `unknown` | 0 | **exit 2** `unsupported encryption handler: filter=Standard, V=4, R=4, CFM=Some("AESVX")` |
| B | `/CFM /AESV2` → 空白 11 バイト | stream/string/file = `none` | 0 | **`RC4`×3** → `rewrite --decrypt` は `WeakCryptoNotAllowed` で exit 2 |
| C | `/StmF /StdCF` → `/StmF /NoSuC` | stream=`unknown`, string=`AESv2`, file=`unknown` | 0 | （A と同じ経路でエラー） |
| D | `/StdCF` → `/Identity`（`/CF` キーと `/StmF` の両方） | stream=`AESv2`, string=`unknown`, file=`AESv2` | 0 | — |
| E | `/StdCF` の値 `<< … >>` → `null`（同長パディング） | stream/string/file = `unknown` | 0 | エラー `/CF entry 'StdCF' is not a dictionary` |
| F | `/CFM /AESV2` → `/CFM 12345 ` | stream/string/file = `none` | 0 | エラー `/CF/StdCF/CFM entry is not a name` |

**A の `--decrypt` 実測**（stream を持つ fixture）:

```
$ /usr/bin/qpdf --password=u --static-id --decrypt s_cfm_unknown.pdf out.pdf
WARNING: s_cfm_unknown.pdf (object 3 0, offset 197): unknown encryption filter for
  strings (check /StrF in /Encrypt dictionary); strings may be decrypted improperly
WARNING: s_cfm_unknown.pdf (offset 420): unknown encryption filter for streams
  (check /StmF from /Encrypt dictionary); streams may be decrypted improperly
qpdf: operation succeeded with warnings; resulting file may have some problems
exit=3
```

- 警告は **strings が先、streams が後**。
- 文書に string も stream も複数あるが警告は **各 1 回だけ** →
  `cf_string = e_aes` / `cf_stream = e_aes` の書き換えによる抑止を確認。
- 出力の content stream は正しく復号されている（AES で復号 → Flate で再圧縮）。
- strings 警告には **オブジェクト帰属あり**（`object 3 0`）、streams 警告には
  **無い**（offset のみ）。

**B の `--decrypt` 実測**: 警告なし・exit 0。出力の content stream は
**暗号文のまま**（`e_none` なので復号段を挿さない）。

## Task 3: `interpret_cf` を移植し、`/CF` 解析を qpdf 準拠にする

**File:** `crates/flpdf/src/reader.rs:4006-4049`（`crypt_filter_modes`）ほか

- `crypt_filter_modes(encrypt, revision)` → `crypt_filter_modes(encrypt, v)`。

- ループ本体を `:862-883` の逐語訳にする:
  - 値が辞書でなければ **skip**（現在は `Malformed` エラー）
  - `method` を `Identity`(`e_none`) で初期化

- `authenticate_if_encrypted` の mode 決定を `:886-904` に置き換える:
  - `V==4 || V==5` のときだけ `cf_stream = interpret_cf(StmF)`,
    `cf_string = interpret_cf(StrF)`, `/EFF` が name なら
    `cf_file = interpret_cf(EFF)` さもなくば `cf_file = cf_stream`

- 不要になる `standard_v4_or_legacy_modes` / `standard_r5_or_r6_modes` /

- `EncryptionState` のフィールド名を `stream_mode`/`string_mode` →
  `cf_stream`/`cf_string` に改名（qpdf 名に合わせる）。

**⚠ V<4 の罠**: `cf_stream` を忠実化すると V=1/V=2 で `Identity` になる。

## 実装結果（計画からの設計変更）

実装中に、計画が `EncryptionMode` を「暗号方式」として使い続ける前提だった点が
qpdf と食い違うと判明したため、以下を変更した。

1. **`EncryptionMode` は crypt filter method 専用にし、暗号の選択は qpdf の
   `use_aes` + 鍵長に戻した。** qpdf は `Pl_AES_PDF` に鍵と鍵長を渡すだけで
   （`libqpdf/Pl_AES_PDF.cc:12-34`）、AES-128 か AES-256 かは
   `compute_data_key` が返す鍵長（`/V >= 5` で 32 バイト、`:337-340`）だけで
   決まる。したがって `/V 5` 上の `/AESV2` は AES-256、`/V 4` 上の `/AESV3` は
   AES-128 になる。`EncryptionMode` を暗号として使うとこれを再現できないため、
   `decrypt_stream_bytes` / `decrypt_object_strings` /
   `decrypt_object_value_strings` は `use_aes: bool` を取る形にした。
   副産物として、到達不能な match アームが消えた。
2. **`compute_data_key` は production 経路に接続した**（Task 5 は「未接続」と
   書いていた）。未接続のままにするのは og キャッシュ（`key_for_object`）だけ。
   `per_object_key` との差は `min(len, 16)` を取る対象（qpdf は `"sAlT"` を
   含めた長さ）だけで、標準ハンドラが認める `/V`・`/R` の組では一致するため、
   出力バイトは変わらない。
3. **`explicit_crypt_mode` は `interpret_cf` に置き換わり、その結果も
   `decryptStream` の同じ switch を通る。** qpdf は `/Crypt` 由来の method でも
   `default:` で `cf_stream` を書き換える（`:1131`）ため。
4. **`EncryptionInfo` の `eff_method` を `Option<&str>` から `&str` に変更**し、
   `v` / `r` は `/Encrypt` の再読みではなく保持した状態から取るようにした
   （qpdf `:727-729`「never look at /Encrypt again」）。CLI 側の
   `unwrap_or(stream_method)` フォールバックは `cf_file` の解決に移った。
5. **`r5_and_r6_reject_unsupported_crypt_filter_methods` は削除ではなく反転**
   （`r5_and_r6_accept_an_rc4_crypt_filter_method`）。qpdf 実測で `/R 6` +
   `/CFM /V2` が `RC4` を報告して exit 0 になることを確認済み。

### 実測で確認した最終状態

probe 10 件すべてで `--show-encryption` が qpdf と一致し、`rc4-40` /
`rc4-128` / `aes2`(V=4 AESV2) / `aes256`(V=5 AESV3) / `s_cfm_unknown` の
復号後 stream も qpdf と一致する（`cf_identity_shadow` のみ、長さが変わる
置換で xref が壊れるため flpdf 側に `--repair` が要る。qpdf が自動再構築する
のに対する既存の差で、本変更とは無関係）。
